## 2. Diagnóstico — duas camadas de RVA obsoleta

`link.exe` reordena/funde seções. `exc.exe`: original
`.text .data .rdata /4 .pdata .xdata .bss .idata .CRT .tls .reloc …` →
rebuildado `.text .rdata .data .pdata .idata _4 .bss .CRT .reloc …`
(a `.idata` saiu de `0x10000` para `0xE000`).

1. **Ponteiro do dir** (`dex_patch_dirs`): copiava a RVA crua → IMPORT
   `0x10000` caía na **`.bss`** nova → `0xC000007B`, `Imports: 0`.
2. **RVAs internas** do `.idata` copiado: `OFT=0x10130`, `Name=0x10AD4`,
   `FirstThunk=0x103C8` (layout antigo) → mesmo com o dir certo, lixo.

## 3. Fatia 2a (esta) — remap por (seção, offset)

Novo `.pd_remap` (local de `dex_patch_dirs`): seção original que contém a RVA
→ `offset` → `VirtualAddress` da **seção homônima** da rebuildada (nome
comparado com a sanitização do gerador, `/NNN` → `_NNN`). Sem homônima ou
offset fora → o dir **não** é copiado (nunca RVA velha). Guarda de slot
`(0,0)` mantida (não sobrescreve dir que o link já produziu).

**Efeito medido:** `exc -native -r` passou de `0xC000007B` (**imagem
inválida**) para `0xC0000005` (**AV**) — a imagem **carrega** agora; falta a
2b.

## 6. Retomada — fatia 2b (import table simbólica no win64)

**Estado de partida:** `build.bat` limpo 1.2.386; `run_tests.bat` **385/385**;
`run_slow.bat` **7/7**; `exc -native -r` = `0xC0000005` (imagem **carrega**,
mas o IAT está lixo). Objetivo da 2b: `exc -native -r` → exit **42** +
stdout `caught=7 cleanups=6`.

**Causa a corrigir:** as RVAs *internas* do `.idata` copiado seguem absolutas
(`OFT`/`Name`/`FirstThunk` e as entradas ILT/IAT apontando p/ `IMAGE_IMPORT_BY_NAME`).
Têm de virar simbólicas (o linker recalcula), como a R-5.3 já faz no `-m bin`.

**Modelo pronto no caminho bin** (`src/gen/rebuild.asm`):
- `.gb_db_slots` (walker de eventos: import dir + hint/name + unwind);
- `.gb_slot_emit` / `.gb_hint_emit` / `.gb_name_emit` (descritor, `dq` de thunk,
  `dw <hint>` + `db "<nome>", 0`, `db "<dll>", 0`);
- `dex_emit_qstr` (**file-scope** — já alcançável do win64);
- offsets simbólicos: `dd label_<alvo> wrt ..imagebase` (win64) via `.pd_field`
  e `dq label_<alvo>` p/ thunks.

**Onde enganchar no win64:** o walker de dados é `.walk_data_sec`
(`.wds_plain_uw`/`.wds_chunks`); os eventos de import precisam entrar como um
conjunto de "boundaries" (como os inícios de unwind da fatia 1) OU criar um
caminho dedicado análogo ao `.gb_db_slots` para a seção da Import Directory.
Cuidado: `.gb_*` são **locais de `dex_generate_bin`** — ou promover os
emissores a file-scope, ou reimplementar no escopo do asm (avaliar).
