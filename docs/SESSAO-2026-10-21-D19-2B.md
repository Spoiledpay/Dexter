## 1. Objetivo

Tornar a import table simbólica no `.asm` gerado por `dexter <pe> -native`
(modo win64), para que o `link.exe` recalcule as RVAs depois de reordenar as
seções (D-19). Antes, a `.idata` saía como `db` cru:

```text
section .idata data
label_140010000:
    db 0x30, 0x01, 0x01, 0x00 …   ; OFT = 0x10130 (layout antigo)
    … 0xD4, 0x0A, 0x01, 0x00 …   ; Name = 0x10AD4
    … 0xC8, 0x03, 0x01, 0x00 …   ; FirstThunk = 0x103C8
```

Com a `.idata` remapeada para `0xE000` pelo link, essas RVAs apontavam para
lixo; a imagem carregava (fatia 2a) e dava `0xC0000005`.

## 2. Implementação

- **Reuso do walker do bin** (`dex_generate_bin.gb_db_slots`) no win64. O
  walker já encontra descritores, IATs, arrays ILT/IAT, hint/name, nomes de
  DLL e unwind por varredura de seção.
- **Grafia por modo** (`g_unwind_bin`):
  - campo de descritor: `dd label_<VA> wrt ..imagebase` (ADDR32NB);
  - thunk de 8 B: `dd label_<VA> wrt ..imagebase, 0` (RVA de 32 bits
    zero-estendida — a IAT pré-load do PE é RVA, não VA);
  - ordinal/bound: `dq 0x<v>` cru;
  - hint/name e nome de DLL: `dw <hint>` + `db "<nome>", 0` / `db "<dll>", 0`.
- **Gaps preservam R-labels/spans** via `.wds_chunks`. Nova flag `g_impwds`
  liga esse caminho só no win64; no bin os gaps seguem `db` (byte-fiel).
- **`-strings`**: `.wds_gap_win` reemite runs como `db "..."` e só degrada
  p/ chunks quando há alvo R no interior do run (splits somariam NULs). O
  gate `[50]` (CR/LF) segue verde e a import table continua simbólica.
- **Seleção de seção** (`.imp_sec_has`): só vai para o walker a seção que
  contém Import Directory, IAT, OFT/Name/FT ou hint/name. As demais mantêm o
  caminho antigo (strings/chunks).
- **Guardas**: `-s <seção>` e `-no-imports` seguem `db` (D-17 — nunca emitir
  símbolo indefinido). x32/win32 segue com import table em `db` (fora do
  escopo do D-19 win64).

## 3. Bug real encontrado no caminho (parser de imports)

`src/pe/pe_imports.asm` (`.fill`): `di` (r10d) era gravado em `[rbp-72]`
**depois** de três `call`s (`dex_rva_to_offset`, `.bounded_cstr`,
`dex_rva_to_offset`). `r10d` é volátil: o valor era lixo; `.thunk_end`
restaurava o lixo e o laço morria no 1º descritor.

Sintomas medidos (antes → depois do fix):

| Binário | imports_count antes | depois |
|---|---|---|
| `tests\exc.exe` | 1 | **69** |
| `tests\var64.exe` | 14 | **62** |
| `tests\hello.exe` | 3 | 3 |
| `tests\notepad.exe` | 315 | 315 |
| `tests\gcc.exe` | 224 | 224 |

O valor antigo do `var64` (14) estava documentado no gate `[16]`; o correto
é 62 (12 descritores, 62 thunks, conferido contra os bytes do PE). Fix: spill
de `di` no topo de `.fill`, antes dos calls; removido o spill tardio.

## 3b. Segundo bug real: nomes `__imp_` duplicados (gcc)

Com o parser corrigido, o `run_slow.bat` acusou `nasm -f bin` falhando no
gcc: `label __imp_..._fileno inconsistently redefined`. O gcc importa
`_fileno`, `_open`, `_read` e `_close` **duas vezes** (dois slots IAT, dois
`IMAGE_IMPORT_BY_NAME` distintos). O nome `__imp_<dll>_<func>` colidia.

Fix: `dex_imp_name_dup` (rcx=img, rdx=entry) devolve 1 se uma entrada
**anterior** tem o mesmo (dll, func|ordinal); nesse caso
`dex_imp_append_rva` anexa `_<iat_rva hex>` ao nome. A 1ª ocorrência fica
pura (`__imp_..._fileno`) e a 2ª vira `__imp_..._fileno_1f8b80`. A regra é
aplicada nos **dois** lados (walker, para a referência; `dex_emit_imp_label`,
para a definição), senão a ref aponta para símbolo inexistente. O `[14]`
ganhou 2 checks com um `fake_imp` de 3 entradas (duplicado + nome único).

## 7. Limite honesto (o que NÃO foi prometido)

- O `.exe` win64 reconstruído do `exc` **ainda dá `0xC0000005`**. A import
  table está válida (69 imports/14 DLLs, dirs 5/5), então o bloqueador agora
  é o **fecho da fatia 2**: `link.exe` funde `.bss`/`.tls`/`.CRT`
  (`LNK4078` múltiplas `.bss`), e o layout resultante não é o do original.
  O `-m bin -native` segue exit 42 (caminho fiel).
- x32/win32 e `-s`/`-no-imports`: import table continua em `db` (D-17).
- O parser corrigido muda `imports_count` de PEs com múltiplos descritores
  (`var64` 14→62) — é o valor correto; gates/oráculos atualizados.

## 8. Armadilhas / lições (para o CTX e próximas sessões)

1. **Voláteis em `dex_pe_parse_imports`:** qualquer spill de `r10d`/`r11d`
   tem de acontecer **antes** dos `call`s. O bug só aparecia quando o
   descritor seguinte existia (exc); `hello`/`notepad` mascaravam.
2. **IAT pré-load é RVA, não VA:** `dq label_<VA>` daria VA de 64 bits. O
   correto é `dd label_<VA> wrt ..imagebase, 0`.
3. **`.gb_db_slots` é local de `dex_generate_bin`:** chamável no win64 por
   `dex_generate_bin.gb_db_slots` (mesmo padrão de
   `dex_generate_asm.wds_chunks`).
4. **Label duplicado:** o caller win64 pré-emite `label_<va_base>:` (o walker
   não emite no offset 0). `.wds_gap_win` não pode reemitir label de run no
   offset 0.
5. **`-strings` × imports:** sem `.wds_gap_win`, os runs viravam `db` nos
   gaps e o `[50]` acusava (CR/LF). Não basta reusar `.wds_chunks` cegamente.
