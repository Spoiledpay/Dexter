## 1. 2c-3 — tail de `.data` (`vsize > raw`)

Medição inicial (`notepad.exe`): `.data` `vsize=0x2740`, `raw=0x1000`,
reconstruída encolhia para `vsize=0x400`; `rip_audit` `sem_label=1238` e
`ptr_audit` 2 qwords congelados em `.rdata`.

Mudanças em `src/gen/rebuild.asm`:

1. `.ptr_tgt_ok` aceita `off < vsize` no modo link (não só `raw`); em
   `-m bin` continua `raw`.
2. `.wds_tail` emite `times N db 0` para `[raw, vsize)` com `label_<VA>:`
   em cada alvo R. O label do início já vem dos chunks; alvo exatamente em
   `raw` ganha label (boundary) e gap zero é omitido.
3. `.wds_ok` chama `.wds_tail` só no modo link, seção não-executável,
   `vsize > emitido`.
4. `tests/rip_audit.py` passou a auditar apenas blocos `db` de seção de
   código (evita decodificar dados como instrução; 702 blocos no notepad).

Fixture controlado: `tests/taildata.asm` (m1/m2 em `.data`),
`tests/taildata_patch.py` (reduz `SizeOfRawData` para `0x400`) e
`tests/taildata_check.py` (vsize/raw, labels dos marcadores, `times`).
`tests/run_tests.bat [58]`: original patchado e rebuildado saem **42**;
`-m bin -native` byte-idêntico.

Resultado `notepad`: `.data` `vsize=0x2740`/`raw>=vsize`, `rip_audit`
`fixable=0`/`sem_label=0`, `ptr_audit` 0. `var64 -native -r` segue exit 0.

## 2. 2c-2 — recusa do EH C++ do GCC

Causa: `__gxx_personality_seh0` + LSDA/`/NNN` com encodings pcrel; o
`link.exe` move seções e não há relocação para offsets relativos entre
seções. O `exc -native -r` carrega mas dá AV dentro de `libstdc++`.

Decisão `docs/adr/0004-recusa-eh-gcc-win64.md` (opção a):

- `src/main.asm` `.has_gcc_eh` varre a import table por
  `__gxx_personality_{v0,seh0,sj0}` e `__gcc_personality_{v0,seh0,sj0}`.
- Com `-native` + `-r` e modo link: exit **4**, stderr
  `dexter: -native -r refused: GCC C++ exception tables are
  position-sensitive (pcrel); use -m bin`.
- `-native` sem `-r` segue; `-m bin -native -r` do `exc` = exit 42.
- Limite: `-no-imports` desativa a detecção (imports não parseados).

Testes: `[57]` cobre recusa (4 + mensagem), geração pura, nasm,
`label_drift`, notepad (`rip_audit`/`ptr_audit`) e `var64` exit 0. Gates
de rebuild que usavam `exc` migraram para `var64` ([54]/[55]/[56]) e
`notepad`.
